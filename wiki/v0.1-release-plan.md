# CivilSimulator 首发版本（v0.1 Tech Preview）开发文档

**开发者：** Zhongjiang Yao  
**文档状态：** 2026-10-06 · R0 门禁已落地（tag `v0.1.0-tech-preview` 待正式打出）  
**结论摘要：** M0–M4 Phase A 已通；**R0 安全 / 配置 / 诚实度门禁已完成**。公开 v1.0 仍否；本地 / 熟人邀测 Tech Preview **在完成手工联调后**可挂。

---

## 1. 结论：现在能不能发？

| 目标 | 是否适合 | 原因 |
|------|----------|------|
| 公开 **v1.0**（多租户、可托管、可续玩） | **否** | 愿景远超现状：多 worker、世界恢复、生产级多模态均未落地 |
| 公开 **v0.1**（互联网可注册） | **否** | Play/WS 鉴权不足、默认密钥、开放 CORS、无限流、进程重启丢世界 |
| **本地 / 熟人邀测 Tech Preview** | **有条件可以** | 单机、已知用户、接受「重启即世界结束」；需完成下文 P0 后再挂公开网 |

应用内部版本号为 `0.4.0`（`backend/app/main.py`），README 已勾选 M0–M4；这表示 **里程碑功能 Phase A 已通**，不等于 **可公开发布**。

## 2. 建议的「第一个 Release」定义

### 2.1 产品命名建议

**CivilSimulator Tech Preview v0.1**（本地单机 / 邀测）

一句话：登录 → 选内建或自定义文明 → 选角 → 3D + 叙事 Play；可选同机邀请加入；系统菜单开关 TTS / BGM / 场景插画。

### 2.2 首发必须承诺（In Scope）

- 注册 / 登录（本地 SQLite 用户）
- 内建种子开局 + 自定义文明规则编辑（M4 Phase A）
- 单人完整 Play 循环（Mock 或本地 Ollama）
- 同进程双人邀请加入（M2 MVP，明确「单 worker」）
- M3 Phase A 氛围层（Pillow 插画 / 浏览器 TTS / 程序化 BGM）
- 金融等实验室作为 **次级** 高级入口（不阻塞主循环）
- 文档：Ollama 模型、单进程 uvicorn、数据目录 `data/runtime/`

### 2.3 首发明确不做（Out of Scope）

- 多 worker / Redis 房间广播 / 云端高可用
- 服务端 TTS、扩散场景图、Hunyuan 场景必开
- 进程重启后自动恢复「活世界」（除非 P0 选择实现 restore）
- 开放公网无门槛注册（无限流 + 默认密钥时）
- 移动端一流 3D 操作
- 每人独立叙事频道、踢人 / 房主转让

### 2.4 成功标准（Release Gate）

1. P0 清单全部完成并通过联调  
2. `LLM_PROVIDER=mock` 全量 pytest 绿  
3. 真实 Ollama 路径：创建 → 推进 3 幕 → 邀请第二账号加入，无鉴权绕过  
4. README / wiki 与能力声明一致（无 Redis / 无「永不丢档」虚假承诺）  
5. 打 Git tag：`v0.1.0-tech-preview`

## 4. 为什么还不能公开发布（关键证据）

### 4.1 安全

| 问题 | 证据 |
|------|------|
| `step` / 多数 Play 突变接口 **无** `get_current_user` | `main.py` `@app.post("/api/sessions/{sid}/step")` 仅查 session 是否存在 |
| WebSocket **无** Authorization | `ws_session` 直接 `accept` |
| 默认 `AUTH_SECRET` | `config.py`：`civsim-dev-auth-secret-change-me` |
| CORS `allow_origins=["*"]` | `main.py` |
| 无限流 | 注册 / step / talk / generator 均可被刷 |

知道 `sid` + `player_id` 即可代操作世界——邀测可接受，**公网不可接受**。

### 4.2 持久化与产品诚实度

| 问题 | 证据 |
|------|------|
| 活世界仅内存 | `session.py` `_SESSIONS` |
| EventStore 可回放 UI，**不**恢复 live Session | `replay_to_tick`；无 `restore_session` |
| Redis 配置存在但未接线 | `config.redis_url` 注释 vs 代码未使用 |
| 前后端默认端口易错 | README/uvicorn `:8000`；`next.config.js` 默认可为 `8001`；WS 按端口启发式 |

### 4.3 工程与发布物

- 无 Dockerfile / compose / `.env.example` / 生产 runbook  
- 无前端单元测试；验收脚本仍有 SKIP 项（含移动端）  
- Generator 在首页门户中与主循环并列，但依赖可选 GPU 服务

## 6. 关键决策：会话在重启后怎么办？

必须在 R0 选定其一，并写进用户可见文案。

### 方案 A — 诚实的短暂世界（更快）

- 重启后 live 世界消失  
- UI 不提供「续玩已死世界」；可提供「回放只读」若 EventStore 仍在  
- 文案：「本预览版世界随服务进程结束」

### 方案 B — 快照恢复（更接近产品）

- 周期 / 休眠时把 Session 序列化到 SQLite 或 EventStore  
- 启动或「继续」时 `restore_session(sid)` 重建 `_SESSIONS`  
- 工作量显著更大（Agent / World / Director 状态完整性）

**v0.1 已选定方案 A**（诚实的短暂世界）。UI / README 文案：本预览版世界随服务进程结束。

## 8. 测试与联调清单（发布前）

### 8.1 自动化

```bash
cd backend && source .venv/bin/activate
QDRANT_ENABLED=false LLM_PROVIDER=mock pytest tests/ -q
```

新增建议用例（R0 完成后）：

- 无 token 调用 `POST /api/sessions/{sid}/step` → 401  
- 非成员 token → 403  
- WS 无 token → 拒绝  
- 默认 `AUTH_SECRET` + `ENV=production` → 进程拒绝启动  

### 8.2 手工联调（Ollama 真路径）

1. 注册两用户；改非默认 `AUTH_SECRET`  
2. 用户 A 创建内建文明并推进 2 幕  
3. 邀请用户 B 加入；双方移动 / 行动互不串号  
4. 创建自定义文明（规则 + 地点）并开局  
5. Esc：TTS / BGM / 场景插画可用  
6. 重启后端：确认与所选方案 A/B 行为一致  
7. Generator 离线时首页不报致命错
