**主题：** 会话可续玩（**方案 B**）。

**产品一句话：** 重启后端后，仍可从快照恢复「活世界」并继续玩（有限一致性承诺）。

#### In Scope

| ID | 功能 | 细节 | 状态 |
|----|------|------|------|
| B-1 | Session 快照序列化 | 周期 + sleep/退出 + lifespan flush → EventStore | ✅ |
| B-2 | `restore_session(sid)` | 重建 World / Society / Director / player；失败明确错误 | ✅ |
| B-3 | 「继续游戏」UX | 「我的世界」续玩按钮；文案改为方案 B | ✅ |

### 3.4 版本 4 — `v0.4.0`

**主题：** 多人房间可运营（社交 + 传输）。

**产品一句话：** 小规模多人同世界可稳定玩；房主有基本管理能力。

#### In Scope

| ID | 功能 | 细节 |
|----|------|------|
| MP-1 | 房间人数上限 UI + 服务端强制 | 默认 8；创建时可配置 |
| MP-2 | 踢人 / 房主转让（MVP） | 仅 host；被踢者 WS 断开 + 成员表更新 |
| MP-3 | 连接与重连体验 | 断线提示、自动重连次数、重连后 hello 恢复绑定 |
| MP-4 | Redis pub/sub **或** 明确单机增强 | **二选一：** (A) 最小 Redis 广播使双 worker 共享房间事件；(B) 仍单进程但完善背压与心跳。推荐 (A) 若目标是公网预览 |
| MP-5 | （可选）简易旁观 / 只读席 | 无行动权成员 |

#### Out of Scope

- 每人独立叙事频道（可标为 v1.0）  
- 匹配大厅 / 排位  
- 语音聊天  

#### 验收

- 4 人同房：移动与 step 不串号；踢人立即生效  
- 若选 Redis：杀一 worker 后另一 worker 仍能广播（或文档写明 failover 限制）  

#### 预估

10–14 日（含 Redis 路径更长）。

#### 依赖

v0.3 续档强烈建议先完成，否则多 worker 下「恢复」更难。

### 3.5 版本 5 — `v0.5.0`

**主题：** 生产硬化与有限公网预览准备。

**产品一句话：** 具备基础账户安全、观测、备份与一条「生产可用」多模态或生成路径，可考虑小流量公网。

#### In Scope

| ID | 功能 | 细节 |
|----|------|------|
| P-1 | 账户：邮箱验证 **或** 魔法链接登录（选一） | 重置密码；邀请码可与邮箱绑定 |
| P-2 | 观测 | 结构化日志；关键路径指标（注册、创建、step 延迟、429 计数）；可选 Sentry |
| P-3 | 备份 | `data/runtime` 备份脚本 + 恢复演练文档 |
| P-4 | CI | GitHub Actions：pytest + tsc；PR 门禁 |
| P-5 | 生产多模态 **一条** 路径 | 例如：服务端 TTS **或** 托管扩散场景图 **或** Hunyuan 文档化必开清单（三选一做透） |
| P-6 | 安全复查 | 依赖审计；密钥轮换说明；关闭残余调试面 |
| P-7 | 限流与配额升级 | 按用户 / 房间的 LLM 日配额，防账单打爆 |

#### Out of Scope

- 完整移动端 3D  
- 全球多区域部署  
- 商业计费完整体系（可只留扩展点）  

#### 验收

- CI 绿；备份恢复演练记录  
- 小流量公网（≤ N 用户）跑 72h 无已知 P0 安全漏洞  
- 选定的多模态路径在「推荐硬件」上可复现  

#### 预估

12–20 日。
